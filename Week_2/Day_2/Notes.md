# Java Constructors Notes (Modules 1--6)

# Q1. What is object initialization?

**Answer:** Object initialization is the process of giving a newly
created object a meaningful starting state.

Object creation lifecycle:

1.  Heap memory is allocated.
2.  Instance variables receive default values.
3.  Field initializers execute.
4.  Instance initializer blocks execute.
5.  Constructor body executes.
6.  Reference is returned.
7.  Reference is assigned to a variable.

------------------------------------------------------------------------

# Q2. Why are default values not enough?

**Answer:**

Default values only make an object memory-safe.

Example:

``` java
class Car {
    String brand;
    int year;
}
```

After:

``` java
Car c = new Car();
```

Values are:

``` text
brand = null
year = 0
```

The object exists but does not represent a meaningful car.

------------------------------------------------------------------------

# Q3. What is a constructor?

**Answer:**

A constructor is a special member of a class whose purpose is to
initialize an already created object.

It does **not** create the object.

The JVM creates the object.

------------------------------------------------------------------------

# Q4. Who creates the object?

**Answer:**

The JVM allocates heap memory when evaluating the `new` expression.

Example:

``` java
Student s = new Student();
```

Conceptually:

``` text
new
↓
JVM allocates memory
↓
Default initialization
↓
Constructor executes
↓
Reference returned
```

------------------------------------------------------------------------

# Q5. What are the rules of a constructor?

**Answer:**

-   Same name as the class.
-   No return type.
-   Invoked automatically by `new`.
-   Used for initialization.

------------------------------------------------------------------------

# Q6. Can constructors be called directly?

**Answer:**

No.

Valid:

``` java
new Student();
```

Invalid:

``` java
Student();      // ❌
s.Student();    // ❌ unless Student is a method
```

Constructors are not ordinary methods.

------------------------------------------------------------------------

# Q7. What is a default constructor?

**Answer:**

A constructor automatically generated by the compiler **only if no
constructor exists** in the class.

Example:

``` java
class Student {
}
```

Compiler generates:

``` java
Student() {
}
```

# Q9. What is a parameterized constructor?

**Answer:**

A constructor that receives parameters.

Example:

``` java
Student(String name, int age) {
    this.name = name;
    this.age = age;
}
```

Benefits:

-   Mandatory data at creation.
-   Prevents partially initialized objects.
-   Cleaner design.

------------------------------------------------------------------------

# Q10. Arguments vs Parameters

Example:

``` java
new Student("Alice", 20);
```

Arguments:

``` text
"Alice"
20
```

Constructor:

``` java
Student(String name, int age)
```

Parameters:

``` text
String name
int age
```

Flow:

``` text
Arguments
↓
Parameters
↓
Instance Variables
```

------------------------------------------------------------------------

# Q11. Why does `name = name;` not work?

Example:

``` java
Student(String name) {
    name = name;
}
```

Java searches variables in this order:

1.  Local variables
2.  Parameters
3.  Instance variables (fields)

So:

``` java
name = name;
```

becomes:

``` text
parameter = parameter
```

The field remains unchanged.

No compilation error occurs.

Correct:

``` java
this.name = name;
```

------------------------------------------------------------------------

# Q12. What is `this`?

**Answer:**

`this` is a reference automatically supplied by the JVM that refers to
the current object whose constructor or instance method is executing.

Conceptually:

``` text
Stack

this
 │
 ▼

Heap

Current Object
```

------------------------------------------------------------------------

# Q13. What does `this.name` mean?

It means:

> Access the field `name` of the object referred to by `this`.

Example:

``` java
this.name = name;
```

Field ← Parameter

------------------------------------------------------------------------

# Q14. When can `this` be omitted?

When there is no local variable or parameter with the same name.

Example:

``` java
class Student {
    int age;

    void display() {
        System.out.println(age);
    }
}
```

Here `age` is interpreted as `this.age`.

------------------------------------------------------------------------

# Q15. What is constructor overloading?

**Answer:**

Multiple constructors with:

-   Same name
-   Different parameter lists

Example:

``` java
Student()

Student(String name)

Student(String name, int age)

Student(String name, int age, double marks)
```

------------------------------------------------------------------------

# Q16. What forms a constructor signature?

A constructor signature includes:

-   Constructor name
-   Number of parameters
-   Types of parameters
-   Order of parameters

It does **not** include parameter names.

Illegal:

``` java
Student(String name)

Student(String studentName)
```

Legal:

``` java
Student(int age)

Student(double age)
```

------------------------------------------------------------------------

# Q17. How does Java choose a constructor?

The compiler compares the arguments with available constructor
signatures.

Example:

``` java
new Student("Alice", 20);
```

Compiler selects:

``` java
Student(String, int)
```

This decision happens at compile time.

------------------------------------------------------------------------

# Q18. What is compile-time selection?

The compiler already knows:

-   Number of arguments
-   Types
-   Order

Therefore it chooses the matching constructor before the program runs.

------------------------------------------------------------------------

# Q19. Why do we need constructor chaining?

Without chaining:

``` java
Student() { ... }

Student(String name) { ... }

Student(String name, int age) { ... }
```

Initialization logic gets duplicated.

Constructor chaining removes duplication by letting one constructor
reuse another.

------------------------------------------------------------------------

# Q20. What is `this()`?

`this()` invokes another constructor of the **same object**.

Example:

``` java
Student() {
    this("Unknown");
}
```

Difference:

``` java
this.name    // access field

this()       // invoke another constructor
```

------------------------------------------------------------------------

# Q21. Does `this()` create another object?

No.

Only one object is created because `new` executes only once.

All constructors operate on the same heap object.

------------------------------------------------------------------------

# Q22. Why must `this()` be the first statement?

Java requires initialization to occur in a predictable order.

Legal:

``` java
Student() {
    this("Unknown");
}
```

Illegal:

``` java
Student() {
    System.out.println("Hello");
    this("Unknown");
}
```

------------------------------------------------------------------------

# Q23. Constructor chaining execution

Example:

``` java
Student() {
    this("Alice");
    System.out.println("A");
}

Student(String name) {
    this(name, 20);
    System.out.println("B");
}

Student(String name, int age) {
    System.out.println("C");
}
```

Execution:

``` text
new Student()

↓

Student()

↓

Student(String)

↓

Student(String,int)

↓

Print C

↓

Return

↓

Print B

↓

Return

↓

Print A
```

Output:

``` text
C
B
A
```

------------------------------------------------------------------------

# Q25. Key Takeaways

-   `new` creates the object.
-   The constructor initializes the object.
-   Constructors are not methods.
-   `this` is a reference to the current object.
-   `this.name` accesses a field.
-   `this()` invokes another constructor of the same object.
-   Constructor overloading is resolved at compile time.
-   Only one object is created during constructor chaining.
-   Every constructor invocation creates a new stack frame.
-   Every constructor implicitly calls `super()` if not explicitly
    chained with `this()`.
